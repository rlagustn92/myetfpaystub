# 💰 MY ETF 급여명세서

### 여러 증권사에 흩어진 내 ETF와 매달 들어오는 돈을 한눈에

미래에셋 앱 열고, 키움 앱 열고, 삼성증권 앱 열고… 그렇게 세 번 확인하던 걸
**한 화면에서** 봅니다.

```
내 ETF 자산        ₩153,240,000
이번 달 ETF 월급      ₩482,300
올해 ETF 월급       ₩3,821,540
세금 계산에 잡히는 금액 ₩2,417,830
```

> **개인정보를 수집하지 않습니다.** 로그인이 없고, 증권사와 연동하지 않으며,
> 입력한 내용은 서버에 저장되지 않습니다. 저장은 **내 브라우저**와 **내려받는
> JSON 파일**로만 이뤄집니다.

---

## 1. 이 앱이 답하는 질문 딱 3개

1. **지금 내 ETF 자산은 얼마인가?**
2. **이번 달/다음 달에 ETF에서 얼마가 들어오는가?**
3. **그 돈 중 세금 계산에 잡히는 금액은 얼마인가?**

투자 분석 앱이 아닙니다. 종목 추천·매수 신호·시장 예측을 하지 않습니다.

---

## 2. 왜 "세금 계산에 잡히는 금액" 을 따로 보여주나

한국 ETF 는 **받은 분배금과 세금이 매겨지는 금액이 전혀 다릅니다.**
그런데 증권사 앱은 보통 받은 금액만 보여줍니다.

실제 데이터입니다 (KODEX 200타겟위클리커버드콜, 2026년):

| 지급월 | 받은 분배금 | 세금 계산에 잡히는 금액 |
|---|---:|---:|
| 9월 | 300원 | **2원** |
| 8월 | 270원 | **3원** |
| 7월 | 323원 | **1원** |
| 4월 | 262원 | **43원** |
| 3월 | 252원 | **33원** |

달마다 1원, 3원, 43원으로 널뜁니다. 그래서 `분배금 × 세율` 로 계산하면 안 되고,
**운용사가 발표한 값을 그대로 가져와야** 합니다. 이 앱이 하는 일이 그겁니다.

지원하는 운용사 (전부 실제 호출해서 확인 — [검증 기록](docs/DATA_SOURCES.md)):

**KODEX**(삼성) · **TIGER**(미래에셋) · **ACE**(한국투자) · **RISE**(KB) ·
**SOL**(신한) · **PLUS**(한화) · **TIME**(타임폴리오) — 843개 종목

그 외 운용사는 분배금만 가져오고, 과세표준은 **`데이터 없음`** 으로 둡니다.
추측해서 채우지 않습니다.

## 5. 쓰는 순서

1. **➕ 종목 관리** 에서 `SCHD`, `069500`, `KODEX 200` 처럼 쳐서 종목을 찾습니다
2. 다섯 가지만 넣습니다 — **증권사 / 계좌 / 종목 / 수량 / 평균 매입가격**
3. 끝입니다. 나머지는 앱이 알아서 가져옵니다

> **최초 매수일과 과거 거래내역은 안 물어봅니다.** 이 앱은 투자일지가 아니라
> "지금 내가 가진 것" 을 관리하는 도구입니다.

같은 ETF 를 여러 증권사에 나눠 가지고 있어도 됩니다.
전체에서는 `SCHD 180주` 로 합쳐 보이고, 눌러 보면 계좌별로 쪼개서 보여줍니다.

## 7. 저장

**자동으로 이 브라우저에 저장됩니다.** 회원가입도 서버 저장도 없습니다.

- 같은 브라우저로 다시 들어오면 그대로 남아 있습니다
- **다른 기기·다른 브라우저에서는 안 보입니다** → 옮기려면 `💾 저장` 탭에서
  JSON 파일로 내려받아 저쪽에서 올리면 됩니다
- 시크릿 모드에서는 창을 닫으면 사라집니다 (앱이 그렇다고 알려 줍니다)

`"내 계좌"`, `"와이프 계좌"` 처럼 **포트폴리오를 여러 개** 만들어 둘 수 있습니다.

## 8. 값의 성격 표시

화면에서 이 셋을 항상 구분합니다.

| 표시 | 뜻 |
|---|---|
| 🟢 **확인** | 운용사가 실제로 발표한 값 |
| 🟡 **예상** | 최근 지급 자료로 계산한 예상값. 실제와 다를 수 있습니다 |
| ⚪ **데이터 없음** | 가져오지 못했습니다. **0원이라는 뜻이 아닙니다** |

특히 `데이터 없음` 과 `0원` 을 같은 것으로 취급하지 않습니다.
과세표준 `0원` 은 운용사가 실제로 "0원" 이라고 발표한 값이고(흔합니다),
`데이터 없음` 은 아직 모른다는 뜻입니다.

**예상값은 이렇게 만듭니다** — 최근 지급 간격으로 다음 날짜를 잡고, **가장 최근
실제 지급액을 그대로** 씁니다. 평균이나 추세를 쓰지 않습니다(설명할 수 없는 숫자를
만들지 않으려고). 지급 이력이 2건 미만이면 **예상하지 않습니다.**

## 10. 데이터 출처

| 항목 | 소스 |
|---|---|
| 미국 가격·분배금 | Yahoo Finance (`yfinance`) |
| 한국 가격 | `FinanceDataReader` (KRX 기반, 수정주가) |
| 한국 종목 목록 | `FinanceDataReader` `StockListing("KRX")`, `StockListing("ETF/KR")` |
| **한국 분배금·주당 과세표준액** | **각 운용사 공식 공개 자료** (§2) |
| 그 외 운용사 분배금 | `yfinance` 한국 심볼(`.KS`/`.KQ`) — 과세표준은 없음 |
| USD/KRW 환율 | `yfinance` `USDKRW=X` → 실패 시 `FinanceDataReader` |

**전부 무료입니다.** 유료 API 를 쓰지 않습니다.

환율 규칙: **과거에 받은 분배금은 그날의 환율로**, 앞으로 받을 것은 지금 환율로
환산합니다. (과거 금액 + 현재 환율 조합은 쓰지 않습니다)

## 11. 문제 해결

| 증상 | 원인 / 조치 |
|---|---|
| 특정 종목이 `데이터 없음` | 그 소스에서 값을 못 가져옴. 다른 종목은 정상 동작합니다. 잠시 뒤 **🔄 정보 업데이트** |
| 과세표준이 `자료 없음` 으로 나옴 | ① 아직 운용사가 발표 전이거나 ② 조사하지 않은 운용사입니다. 추측해서 채우지 않습니다 |
| 첫 화면이 느림 | TIGER 는 달마다 따로 조회해야 해서 처음 한 번이 20초쯤 걸립니다. 그 뒤 12시간은 즉시 |
| 다른 기기에서 내용이 안 보임 | 브라우저 저장은 그 기기에만 남습니다. `💾 저장` 에서 JSON 으로 옮기세요 |
| 값이 추정으로 채워지는 것 아닌가? | 아닙니다. 없으면 `데이터 없음`, 예상이면 🟡 예상 이라고 적습니다 |

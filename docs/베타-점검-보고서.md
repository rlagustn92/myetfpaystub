## 1. 찾아서 고친 버그 (6개)

넷은 **에러가 안 나고 조용히 틀리는** 종류였습니다. 그래서 위험합니다 —
화면은 멀쩡해 보이는데 숫자만 틀리고, 눈으로 볼 때까지 아무도 모릅니다.

### 🔴 남의 JSON 파일 하나로 등록해 둔 ETF 가 전부 사라졌습니다

가장 심각한 것이었습니다.

불러오기가 `schema` 키가 **없으면** 그냥 통과시켰습니다. 그래서 `{"nope":1}`,
`[]`, 다른 앱에서 내보낸 JSON 도 "성공" 으로 받고 **빈 포트폴리오**를
돌려줬습니다. 그 빈 내용이 화면 맨 아래에서 브라우저 저장소에 그대로 덮여
써지므로, **파일 하나 잘못 열면 그동안 등록한 게 전부 날아갑니다. 경고도 없이.**

→ 이제 "우리 파일처럼 생겼는지" 를 먼저 봅니다. 아니면 **불러오지 않고**
"등록해 둔 내용을 지우지 않으려고 불러오지 않았습니다" 라고 알립니다.
`schema` 가 없던 옛 저장본은 그대로 열립니다.

### 🔴 평단가 오타가 조용히 0원으로 저장됐습니다

`1.2.3` 처럼 점을 두 번 찍으면 **아무 말 없이 평단가 0원**이 됐습니다.
그러면 투자 원금이 0 이 되고 수익률이 터무니없이 나오는데, 화면 어디에도
"이상하다" 는 말이 없습니다.

→ 못 읽으면 `0` 이 아니라 **"못 읽었다"** 로 돌려주고, 경고를 띄우고,
**저장 버튼을 막습니다.** 숫자를 지어내지 않는다는 규칙은 입력칸에도 똑같이
적용되어야 합니다.

### 🟠 "3만" 을 3원으로 읽었습니다

한국 사람은 만 단위로 셉니다. `3만` 을 3 으로 읽으면 평단가가 **1/10,000** 이
됩니다.

→ `3만` · `1억` · `32,000원` · `₩32,000` 을 전부 읽습니다.
⚠ `3만5천` 처럼 섞인 표현은 **맞히려 들지 않습니다.** 틀린 숫자를 저장하느니
다시 묻는 편이 낫습니다.

### 🟠 읽은 값과 보여준 값이 달랐습니다

`3만` 을 30,000 으로 **읽어놓고** 화면에는 `3` 이라고 **찍었습니다.**
두 함수를 따로 만들어서 생긴 일입니다.

→ 보여주는 글자를 읽은 값에서 만들도록 묶었습니다. 테스트가 둘이 항상 같은지
검사합니다.

### 🟡 원화 평단가에 소수점이 남았습니다 (요청하신 것)

편집 표가 `32000.0000` 으로 보였습니다. 1원 미만은 실제로 존재하지 않습니다.

→ **원화는 소수점을 버리고 달러만 살립니다.**
입력칸도 통화에 따라 다르게 찍습니다 (`32,000` / `30.5`).

### 🟡 종목별 상세의 카드 5장이 세로로 쌓였습니다

`cols=5` 로 격자를 요청했는데 CSS 에 `.grid.c5` 가 없어서 격자가 안 잡혔습니다.
**에러가 안 나고 한 줄로 쭉 쌓입니다.**

→ 고쳤고, 앱이 쓰는 칸수가 CSS 에 다 있는지 검사하는 테스트를 붙였습니다.

## 2. 확인했더니 멀쩡했던 것

- **다섯 탭 전부** — 빈 포트폴리오에서도, 예시 포트폴리오에서도 안 죽습니다.
- **저장 → 불러오기 왕복** — 앞의 0 이 붙은 종목코드(`0219E0`), 소수점 수량
  (0.3271), 전술판 자리, 스킨, 포트폴리오 이름이 전부 살아남습니다.
- **가격을 못 가져온 종목** — 평가액에서 빼고 "빠졌다" 고 알립니다.
  원금에서도 같이 빼는데, 이건 **의도된 것**입니다(한쪽만 빼면 손익이 틀어집니다).
- **모바일 375px** — 가로 스크롤 없고 카드가 1열로 접힙니다.
- **붙여넣기 가져오기** — 계좌번호 네 가지 형태를 전부 걸러냅니다.

## 3. 성능

측정값입니다 (종목 5개 기준).

| | 고치기 전 | **고친 뒤** |
|---|---|---|
| **캐시 빈 상태** (서버가 자다 깨어남) | 4.96초 | **3.53초** |
| 그다음부터 | 0.00초 | **0.00초** |

내역(고친 뒤): 분배금 2.07초 · 현재가 1.31초 · 환율 0.14초 · 계산 0.00초.
HTTP 는 종목 5개에 14회입니다.

이번에 **분배금을 여러 갈래로 나눠 받게** 고쳤습니다(3.55초 → 2.07초).
종목마다 차례로 기다리던 것을 스레드 4개로 나눴습니다.
⚠ 4개보다 올리지 않습니다 — 빨라지자고 남의 서버를 한꺼번에 두드리면
운용사가 우리를 막고, 그러면 과세표준이 통째로 사라집니다(실제로 겪었습니다).

그 앞에는 20~35초였습니다. TIGER 월별 표를 저장소 파일로 굳힌 덕이 큽니다
(종목당 43회 → 1회).

**남은 것:**

1. **첫 화면을 먼저 그리고 분배금은 나중에** — 자산 숫자는 1.4초면 나옵니다.
   배당금 칸만 "불러오는 중" 으로 두면 체감이 2배 빨라집니다.
   구조를 건드리는 일이라 이번엔 안 했습니다.
2. **KODEX·ACE·RISE 도 시드 파일로** — TIGER 처럼 굳히면 0회가 되지만,
   이쪽은 종목 단위라 843개를 미리 만들어야 해서 비용 대비 실익이 적습니다.

## 4. 넣으면 좋겠다 싶은 것

실제로 써 보면서 "이게 없네" 싶었던 순서대로 적었습니다.

### A. 바로 하면 좋을 것

**✅ ① 분배금 병렬 조회 — 이번에 했습니다**
3.55초 → 2.07초.

**✅ ② 배당금 달력에 "오늘" 표시 — 이번에 했습니다**
오늘 칸에 진한 테두리가 들어갑니다. 달력에서 눈이 헤매지 않습니다.

**③ 첫 화면 단계적 표시 — 아직입니다**
자산은 1.4초, 배당금은 3.5초. 지금은 둘 다 기다립니다. 나눠 그리면 체감이
확 달라집니다. 다만 화면 구조를 건드려야 해서 다음으로 미뤘습니다.

**④ 종목 추가 후 "하나 더 넣기" 흐름**
지금은 저장하면 검색어가 비워집니다. 같은 계좌에 여러 개를 넣을 때
**증권사·계좌는 남고 종목만 비는** 지금 동작이 맞는데, 저장 직후 검색칸에
커서가 가면 연속 입력이 훨씬 빨라집니다(Streamlit 에서 포커스를 옮기는 게
까다로워 방법을 더 찾아봐야 합니다).

### B. 조금 더 큰 것

**✅ ⑤ 연간 배당금 목표와 진행률 — 넣었습니다**
"올해 200만원 받기" 를 정해 두면 진행 막대가 뜹니다. **받은 돈은 진한 색,
들어올 것으로 보이는 돈은 흐린 색**으로 잇대어 그립니다 — 섞으면 "벌써 다
받은 것" 처럼 보여서요. 목표는 사용자가 정하고, 앱은 추천하지 않습니다.
남은 금액을 "이만큼 더 사면 됩니다" 로 바꾸지도 않습니다(그건 매수 추천입니다).

**✅ ⑥ 월별 추이에 작년 비교 — 넣었습니다**
막대 뒤에 작년 같은 달이 흐리게 겹칩니다. 높이는 **두 해를 합쳐** 가장 큰
값으로 재야 작년 막대가 칸을 안 뚫습니다.

**✅ ⑦ 종목별 배당 성장 — 넣었습니다**
최근 1년과 그 전 1년의 **주당 실제 지급액**을 나란히 놓습니다.
⚠ "앞으로도 그만큼 나온다는 뜻이 아닙니다" 를 화면에 적었습니다.
⚠ 예상값은 안 셉니다(늘어난 게 예상 때문인지 알 수 없게 됩니다).
⚠ 상장한 지 얼마 안 된 종목은 **비교하지 않습니다** — 없는 기간을 0 으로
세면 성장률이 무한대로 나옵니다.

**✅ ⑧ 붙여넣기 "기존과 합치기" — 넣었습니다**
같은 증권사·계좌에 같은 종목이 있으면 **덮어쓰기 / 수량 더하기 / 건너뛰기**
를 물어봅니다. 수량을 더할 때 평단가는 **수량으로 가중평균**합니다 —
새 값으로 그냥 덮으면 원금이 틀어집니다.

### C. 나중에

**⑨ 배당락일 알림** — 브라우저 알림은 앱이 켜져 있어야 해서 한계가 있습니다.
**⑩ 여러 포트폴리오 비교** — 자료 구조는 이미 열려 있습니다.

## 5. 아직 못 한 것 (제 눈에 걸리는 것)

**① 증권사별 보유·종목별 상세가 패널 밖에 있습니다**
`st.expander` 같은 위젯은 제가 만든 `<div>` 안에 못 넣습니다. Streamlit 이
위젯을 자기 컨테이너에 그리기 때문입니다. 내부 DOM 을 CSS 로 잡는 방법이
있지만 버전이 올라가면 조용히 깨져서 아직 안 썼습니다.

**② 상단 이모지 다섯 개**
`🏠 홈 · 📅 월별 급여명세서 · 🔎 종목별 상세 · ➕ 종목 관리 · 💾 저장` —
이모지가 제목보다 눈에 띕니다. 덜어내는 방향이라면 이것도 후보입니다.
다만 손에 익으셨을 수 있어 건드리지 않았습니다.

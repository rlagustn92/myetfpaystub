# 데이터 소스 검증 결과 (Phase 1)

**검증일 2026-09-20. 아래 모든 내용은 그날 실제로 호출해서 응답을 확인한 값입니다.**
"될 것 같다" 로 적은 항목은 없습니다. 확인하지 못한 것은 확인하지 못했다고 적었습니다.

> 이 문서의 목적은 하나입니다 — **한국 ETF의 월별 "주당 과세표준액" 을 무료로 자동
> 수집할 수 있는가.** 이게 안 되면 이 서비스의 절반은 만들 수 없습니다.
>
> **결론: 된다.** 국내 7개 주요 운용사가 모두 공개하고 있고, 전부 파싱에 성공했습니다.

## 0. 한 장 요약

| 필요한 것 | 미국 ETF | 한국 ETF |
|---|---|---|
| 현재가격 | yfinance (`Ticker.history`) | FinanceDataReader (`DataReader`) |
| 종목명·검색 | 자체 시드 + yfinance 실조회 | FDR `StockListing("KRX"/"ETF/KR")` |
| 주당 분배금 | yfinance `.dividends` | **운용사 공식 자료** → 실패 시 yfinance `.KS/.KQ` |
| 지급 기준일 | 배당락일(ex-date)만 제공 | **운용사 공식 자료** (지급기준일 + 실지급일 둘 다) |
| 주당 과세표준액 | **해당 없음** (§4 참고) | **운용사 공식 자료** |
| USD/KRW 환율 | yfinance `USDKRW=X` → FDR `USD/KRW` | 〃 |

**비용 0원.** 유료 API 없음. Alpaca 는 키가 있으면 미국 최신가/분배금에 얹어 쓸 수
있지만(키 기준 할당량이라 배포 시 유리), **없어도 전부 동작합니다.**

## 1. 왜 "분배금 × 세율" 로 계산하면 안 되는가 — 실측

이게 이 서비스를 만드는 이유입니다. **분배금과 과세표준은 전혀 다른 숫자입니다.**

KODEX 200타겟위클리커버드콜(498400) 실제 데이터:

| 지급기준일 | 주당 분배금 | 주당 과세표준 |
|---|---:|---:|
| 2026-09-15 | 300원 | **2원** |
| 2026-08-14 | 270원 | **3원** |
| 2026-07-15 | 323원 | **1원** |
| 2026-06-15 | 350원 | **미발표** |
| 2026-04-15 | 262원 | **43원** |
| 2026-03-13 | 252원 | **33원** |

같은 종목인데 달마다 1원, 3원, 43원으로 널뜁니다. 반면 KODEX 200(069500)은
대체로 분배금 = 과세표준이고, 가끔 어긋납니다(2026-07: 183원 / 168원).

> **그래서 규칙 하나: 과세표준은 반드시 별도 필드로 받아온다.**
> 분배금에서 유도하지 않는다. 없으면 `데이터 없음` 으로 둔다.

또 하나 중요한 구분이 있습니다.

- **`0원`** — 운용사가 "과세표준 0원" 이라고 **발표한** 값입니다 (실제로 흔합니다.
  TIGER 반도체TOP10커버드콜액티브 2026-09: 분배금 177원 / 과세표준 0원).
- **`미발표`** — 아직 값이 없는 것입니다.

**이 둘을 같은 것으로 취급하면 안 됩니다.** 코드에서 `0` 과 `None` 을 섞지 않습니다.

## 2. 운용사별 검증 결과

국내 ETF 순자산 기준 상위 7개 운용사를 전부 확인했습니다.
(시장의 대략 95% 이상이 여기 들어갑니다.)

| 브랜드 | 운용사 | 분배금 | 지급기준일 | 실지급일 | 과세표준 | 형태 |
|---|---|:-:|:-:|:-:|:-:|---|
| KODEX | 삼성 | ✅ | ✅ | ✅ | ✅ | JSON API |
| TIGER | 미래에셋 | ✅ | ✅ | ✅ | ✅ | HTML 조각(POST) |
| ACE | 한국투자 | ✅ | ✅ | ✅ | ✅ | JSON API |
| RISE | KB | ✅ | ✅ | ✅ | ✅ | JSON API |
| SOL | 신한 | ✅ | ✅ | ✅ | ✅ | JSON API (⚠ §2-5) |
| PLUS | 한화 | ✅ | ✅ | ✅ | ✅ | SSR HTML |
| TIME | 타임폴리오 | ✅ | ✅ | ✅ | ✅ | SSR HTML |
| KIWOOM | 키움 | ✅ | ✅ | ✅ | ✅ | **붙이지 못함 — TLS 문제(§2-8)** |

### 넣지 못한 곳 — KIWOOM (키움투자자산운용, 옛 KOSEF·히어로즈)

**자료는 있습니다.** `https://www.kiwoometf.com/service/report/KO03020000M` 에
`분배금 지급 기준일 / 분배금 지급일 / 주당분배금 / 분배율(%) / 주당과세표준액` 표가
그대로 있고, 상품 페이지는 `?gcode=069660` 처럼 **6자리 종목코드로 바로** 열립니다.
매핑도 필요 없어서 붙이기 제일 쉬운 축입니다.

**그런데 파이썬에서 못 받습니다.** 그 서버가 TLS 중간 인증서를 같이 안 보냅니다.

```
requests.get("https://www.kiwoometf.com/...")
-> SSLCertVerificationError: unable to get local issuer certificate
```

브라우저는 빠진 인증서를 알아서 받아오지만(AIA), 파이썬은 안 그럽니다. 사이트 잘못이지
우리 잘못은 아닙니다. **`verify=False` 로 끄지 않았습니다** — 남의 서버를 부르면서
TLS 검증을 꺼두면 그때부터는 중간에서 내용이 바뀌어도 알 수 없습니다. 고작 종목
2%를 더 붙이자고 할 일이 아닙니다.

저쪽이 인증서 설정을 고치면 **provider 파일 하나만 추가하면 됩니다**(HTML 표 파서를
그대로 쓰면 되고, 열 순서는 이미 머리글 이름으로 찾습니다). 그때까지는 일반 폴백으로
내려가 `과세표준 데이터 없음` 으로 표시됩니다.

### 그 밖

HANARO(NH아문디) · WON(우리) 등은 **아직 조사하지 않았습니다.**
확인하지 않은 것을 "없다" 고 적지 않습니다 — 코드에서는 일반 폴백(§3)으로 넘어가고,
화면에는 `과세표준 데이터 없음` 으로 표시합니다.

### 2-1. KODEX (삼성자산운용)

```
GET https://www.samsungfund.com/api/v1/kodex/distribution.do
    ?pageNo=1&ordrColm=BASIC_D&period=0&ordrSort=DESC&srchVal={종목코드}
Referer: https://www.samsungfund.com/etf/product/distribution.do
```

`srchVal` 에 **6자리 종목코드를 그대로** 넣으면 됩니다. 별도 매핑이 필요 없습니다.
`period=0` 이 전체 기간, 한 페이지 12건이라 `totalCnt` 를 보고 페이징합니다.

응답 `dividList[]` 의 쓰는 필드:

| 필드 | 뜻 |
|---|---|
| `stkTicker` | 종목코드 (`0219E0` 처럼 영문 섞인 것도 있음) |
| `basicD` | 지급기준일 `YYYYMMDD` |
| `payD` | 실지급일 `YYYYMMDD` |
| `dividA` | 주당 분배금 |
| `taxDividA` | **주당 과세표준액** (미발표면 `null`) |
| `dividY` | 분배율(%) |

### 2-2. TIGER (미래에셋자산운용)

```
POST https://investments.miraeasset.com/tigeretf/ko/distribution/overall/list.ajax
form: pageIndex=1 listCnt=300 orderType=B orderB=ratioDESC
      selectYear=2026 selectMonth=9 orderC= q=
```

응답은 `<tr>` HTML 조각입니다. 열 순서가 곧 스키마입니다:

```
종목명 / 유형 / 지급기준일 / 실지급일 / 주당분배금(원) / 주당과세표준액(원) / 분배율(%)
```

종목코드는 행 안의 `getEtfDtlPop('KR7360750004', ...)` 에서 꺼냅니다.
**ISIN 의 3~8번째 글자가 6자리 단축코드입니다** (`KR7360750004` → `360750`,
`KR70177R0000` → `0177R0`).

⚠ **`selectMonth` 를 비우면 그 해의 합계만 오고 날짜가 빕니다.** 개별 지급 건을
받으려면 반드시 월을 지정해야 합니다. 그래서 이 provider 는 **종목 단위가 아니라
(연,월) 단위로 받아서 캐시**합니다 — 한 번 호출로 그 달의 TIGER 전 종목이 다 옵니다.
종목마다 부르는 것보다 호출 수가 훨씬 적습니다.

### 2-3. ACE (한국투자신탁운용)

```
GET https://papi.aceetf.co.kr/api/funds/{fundCd}/dividend?page=1
GET https://papi.aceetf.co.kr/api/funds?page=1&size=1000      ← 목록(매핑용)
```

가장 깔끔한 JSON 입니다. 필드:
`std_DT`(기준일) · `dividend_DT`(지급일) · `dividend_PRI`(분배금) ·
**`tax_PRI`(주당 과세표준액)** · `dividend_RATE`(분배율).

ACE 는 종목코드가 아니라 **펀드코드(`K55101DU0363`)** 로 조회합니다.
목록 API 의 `stockCd`(ISIN) → `fundCd` 매핑이 필요합니다.

### 2-4. RISE (KB자산운용)

```
GET https://kbam.co.kr/api/products/etfs/{fund_cd}/dividend
GET https://kbam.co.kr/api/products/etfs                       ← 목록(매핑용)
```

**한 번 호출로 전체 이력이 옵니다.** `history[]` 안에
`base_date` · `payment_date` · `amount` · **`tax_standard_amount`** · `dividend_ratio`.
목록의 `krx_cd` → `fund_cd` 매핑이 필요합니다.

### 2-5. SOL (신한자산운용) — ⚠ 필드 이름에 속지 말 것

```
GET https://www.soletf.com/api/etf/pds/dividend/{fundId}
```

`items[]` 필드가 **이름과 뜻이 어긋납니다.** 실제 화면과 대조해서 확인했습니다.

| 필드 | 실제 뜻 |
|---|---|
| `WORK_DT` | 지급기준일 |
| `DIVIDEND_DT` | 실지급일 |
| `DIVIDEND_PRI` | 주당 분배금 |
| **`WEEK_PRI`** | **주당 과세표준액** ← 이름이 "주간"처럼 보이지만 과세표준입니다 |
| `TAX_PRI` | 과세기준가격(NAV성 값, 9,102.27 같은 큰 수). **과세표준 아님** |
| `BFAS_STAS_STPR` | 전일 과세기준가격 |

`TAX_PRI` 를 과세표준으로 쓰면 주당 9,102원짜리 과세표준이 되어 **숫자가 45배쯤
틀립니다.** 에러는 안 납니다. SOL 미국30년국채커버드콜(합성) 32건 전부를 사이트
화면 표와 대조해 `WEEK_PRI` 가 맞다는 것을 확인했습니다.

`fundId` 는 6자리 내부 번호(`211044`)라 매핑이 필요합니다
(목록: `https://www.soletf.com/ko/fund` HTML).

### 2-6. PLUS (한화자산운용)

```
GET https://www.plusetf.co.kr/product/detail?n={상품번호}
```

서버가 완성된 HTML 을 줍니다. 페이지 안의
`분배금 지급현황` 표(`지급 기준일 / 실 지급일 / 분배금(원) / 주당과세표준액(원)`)를 읽습니다.
종목코드는 `<div class="summary__product-code">161510</div>` 에 있습니다.
목록은 `https://www.plusetf.co.kr/product/overview` (86종목).

⚠ 상세 페이지가 250KB 쯤 됩니다. 반드시 캐시하고, 목록 크롤링은 배치로만 합니다.

### 2-7. TIME (타임폴리오자산운용)

```
GET https://timeetf.co.kr/m11_view.php?idx={번호}
GET https://timeetf.co.kr/m11_list.php?cate=001|002     ← 목록(18종목)
```

역시 SSR HTML. `지급기준일 / 실지급일 / 분배금액(원) / 주당과세표준액(원)` 표.
종목코드는 `<title>` 의 `TIME 미국나스닥100액티브(426030)` 에서 꺼냅니다.

## 3. 운용사를 못 찾았을 때 (일반 폴백)

yfinance 의 한국 심볼로 **분배금만** 받습니다.

```python
yf.Ticker("069500.KS").dividends   # 56건
yf.Ticker("498400.KS").dividends   # 21건 (금액이 KODEX 공식값과 일치)
```

- 인덱스는 **배당락일**입니다(지급기준일 다음 영업일이 아니라 그 하루 전).
  운용사 자료의 "지급기준일" 과 하루 차이가 날 수 있으므로, 출처가 다르면
  **날짜 기준이 다르다는 것을 화면에 밝힙니다.**
- **과세표준은 얻을 수 없습니다.** `데이터 없음` 으로 둡니다. 추정하지 않습니다.
- 6자리 코드에 `.KS` → `.KQ` 순으로 시도합니다. ⚠ `isdigit()` 로 거르면 안 됩니다
  — `0219E0` 처럼 영문이 섞인 코드가 실제로 있고, 그쪽도 데이터가 있습니다.

## 4. 미국 ETF 의 과세표준

**한국 ETF 의 "주당 과세표준액" 에 해당하는 개념이 미국 상장 ETF 에는 없습니다.**
미국 ETF 는 운용사가 그런 값을 발표하지 않습니다(한국 세법상의 과표기준가 개념이라서).

한국 거주자가 미국 ETF 분배금을 받으면 **지급액 전체가 원천징수 대상**이 됩니다.
그래서 이 앱에서는 미국 ETF 의 "세금 계산에 잡히는 금액" 을 **분배금 전액**으로 봅니다.
따로 조회하지 않고, 화면에도 그렇게 적습니다.

> 이건 세무 자문이 아닙니다. 앱은 금액만 보여주고, 세율을 곱해 "낼 세금" 을
> 확정값처럼 표시하지 않습니다.

## 5. 호출 부하와 캐시 설계

무료 소스로 버티는 요령은 캐시 키 설계입니다. **기간이 달라도 같은 데이터면 같은 키.**

| 키 | TTL | 근거 |
|---|---|---|
| `kr:dist:{issuer}:{ticker}` | 12h | 전체 이력을 받아 캐시하고 화면에서 잘라 씀 |
| `kr:dist:tiger:{YYYY}-{MM}` | 12h | TIGER 는 월 단위 — 한 번에 그 달 전 종목 |
| `issuer:index` | 24h | 종목코드 → 운용사 내부 ID 매핑 (시드 CSV 우선) |
| `us:div:{ticker}` | 12h | yfinance 는 어차피 전체를 줌 |
| `us:last:{ticker}` / `kr:last:{ticker}` | 15m | 최신가 |
| `fx:usdkrw:latest` | 1h | 환율 |
| `search:kr:universe` | 24h | 상장/폐지는 드묾. 목록이 제일 무거움 |

**실패는 캐시하지 않습니다.** 그래야 `🔄 정보 업데이트` 버튼이 의미가 있습니다.

종목코드 → 운용사 내부 ID 매핑은 **저장소에 시드 CSV(`data/issuer_index.csv`)로
넣어둡니다.** 실행할 때마다 운용사 사이트 목록을 긁으면 첫 화면이 몇십 초씩 걸리고,
남의 서버에도 예의가 아닙니다. 시드를 다시 만드는 스크립트는
`tools/build_issuer_index.py` 이고, **개발자 PC 에서만** 돌립니다.

## 6. 확인하지 않은 것 (정직하게)

- KOSEF(키움) · HANARO(NH) · WON(우리) 등 나머지 운용사 — 조사 안 함. 폴백으로 처리.
- 각 운용사 API 의 요청 한도 — 공식 문서가 없어 모름. 캐시와 타임아웃으로 방어.
- 위 엔드포인트들은 **공식 공개 API 가 아닙니다.** 언제든 바뀔 수 있다는 전제로
  쓰고, 실패하면 값을 지어내지 말고 `데이터 없음` 으로 떨어지게 만들었습니다.
- 과거 분배금의 "실제 내 계좌 입금액" 은 증권사 연동 없이는 알 수 없습니다.
  이 앱은 **상품 기준 금액**만 계산하고, 실제 입금액과 다를 수 있다고 밝힙니다.

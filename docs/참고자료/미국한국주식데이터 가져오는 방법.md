# 미국·한국 주식 데이터 가져오는 방법 — 전수 인계서

> 이 문서를 읽는 AI/개발자에게.
>
> 이건 "API 문서"가 아닙니다. **실제로 돈 안 들이고 미국·한국 주식의 가격·분배금·분할·환율을
> 전부 가져와서 서비스로 굴려본 사람이, 피 본 것까지 다 적어놓은 기록**입니다.
> 여기 적힌 함정들은 전부 한 번씩 실제로 당해본 것들입니다. 특히 ⚠ 표시가 붙은 것은
> 모르고 지나가면 **숫자가 조용히 틀립니다.** 에러가 안 나고 틀려서 더 위험합니다.
>
> 순서대로 읽으면 됩니다. 급하면 §1(설계) → §2-3의 ⚠⚠(제일 큰 함정) → §7(캐시) → §9(이식 순서).

## 0. 한 장 요약

| 필요한 것 | 미국 | 한국 |
|---|---|---|
| 최신가 | **Alpaca** `/v2/stocks/{sym}/trades/latest` → 실패 시 yfinance | FinanceDataReader 일봉의 마지막 행 |
| 가격 히스토리 | **yfinance** `Ticker.history()` → 실패 시 Alpaca `/v2/stocks/{sym}/bars` | FinanceDataReader `DataReader()` |
| 분배금(배당) | **Alpaca** `/v1/corporate-actions` → 실패 시 yfinance `.dividends` | yfinance `{코드}.KS` / `{코드}.KQ` → 없으면 사용자 직접 입력 |
| 분할 | **yfinance** `.splits` → 실패 시 Alpaca corporate-actions | yfinance (없으면 빈 값. FDR 종가가 이미 수정주가라 괜찮음) |
| 환율 USD/KRW | yfinance `USDKRW=X` → 실패 시 FinanceDataReader `"USD/KRW"` | 〃 |
| 종목 목록/검색 | 자체 시드 목록 + yfinance 실조회 | FinanceDataReader `StockListing("KRX")`, `StockListing("ETF/KR")` |

**총비용 0원.** Alpaca 무료 티어 + yfinance(무료) + FinanceDataReader(무료).
유료로 가야 하는 경우는 딱 하나 — 미국 **통합시세(SIP) 종가가 소수점까지 정확해야 할 때**.
포트폴리오 구성·분배금 계산 용도로는 무료 티어로 충분합니다.

## 1. 설계의 뼈대 — 왜 이렇게 만들었나

### 1-1. 구조

```
UI (화면)
   ↓  화면은 데이터 소스를 전혀 모릅니다
Service (계산 로직: 분배금 TTM, 백테스트, 원화 환산…)
   ↓  get_provider("US") / get_provider("KR")
MarketDataProvider  ← 추상 인터페이스 (메서드 5개뿐)
   ↓
Alpaca / yfinance / FinanceDataReader
```

인터페이스는 **딱 5개**입니다. 이것만 지키면 소스를 통째로 갈아끼워도 위층이 안 바뀝니다.

```python
get_latest_price(ticker)              -> PriceQuote(price, currency, as_of, source)
get_price_history(ticker, start, end) -> DataFrame(index=날짜, columns=["close"])
get_distributions(ticker, start, end) -> Series(index=배당락일, value=주당 분배금)
get_splits(ticker, start, end)        -> Series(index=날짜, value=분할비율)
get_listing_first_date(ticker)        -> date | None   (기본 구현 제공)
```

**소스 교체 지점은 파일 하나(`registry.py`)입니다.** yfinance 가 막히든 Alpaca 가 유료화되든
이 파일만 고칩니다. 이걸 안 지키고 서비스 코드에서 `yf.Ticker(...)` 를 직접 부르기 시작하면
나중에 소스를 못 바꿉니다. **위층에서 라이브러리를 직접 부르지 마세요.** 이거 하나가
나중에 며칠을 아껴줍니다.

```python
@lru_cache(maxsize=None)
def get_provider(market: str) -> MarketDataProvider:
    m = (market or "").upper()
    if m == "US":
        if alpaca_provider.is_configured():
            return USCompositeProvider(AlpacaDataProvider(), USDataProvider())
        return USDataProvider()          # 키 없으면 yfinance 단독으로도 동작
    if m == "KR":
        return KRDataProvider()          # 한국 종목은 Alpaca 에 없음
    raise ValueError(f"알 수 없는 시장: {market!r}")
```

### 1-2. 절대 원칙 — 데이터가 없으면 없다고 한다

```python
class DataUnavailable(Exception):
    """메시지는 그대로 사용자에게 보여줄 수 있는 문장으로 쓴다."""
```

- 값이 없으면 **0으로 채우지 않습니다.** 0은 "분배금이 없다"는 뜻인데 사실은 "모른다"입니다.
  이 둘을 섞으면 사용자가 "이 종목은 배당이 안 나오는구나"로 오해합니다.
- **비슷한 종목 값을 대신 쓰지 않습니다.**
- 추정을 해야만 하면 **추정이라고 화면에 밝히고 근거(지급 횟수·관측 일수)를 같이 보여줍니다.**
- 예외 메시지는 영어 스택트레이스가 아니라 **사용자가 읽을 한국어 문장**으로 씁니다.
  그래야 위층이 그대로 화면에 뿌릴 수 있습니다.

이 원칙이 왜 중요하냐면, **금융 데이터는 틀려도 그럴듯해 보이기 때문**입니다.
사용자는 검산할 방법이 없습니다. 그래서 "모른다"고 말할 수 있는 능력이 정확도보다 중요합니다.

### 1-3. 가격 규약 — 분할은 반영, 배당은 미반영

모든 계산의 전제입니다. **한 줄로 외우세요.**

> **close = 분할은 소급 반영, 배당은 반영 안 함. 배당은 언제나 따로 받는다.**

| 소스 | 설정 | 결과 |
|---|---|---|
| yfinance | `auto_adjust=False` 의 `Close` | 분할 소급 ✓ / 배당 미반영 ✓ |
| Alpaca | `adjustment=split` | 분할 소급 ✓ / 배당 미반영 ✓ |
| FinanceDataReader (한국) | 기본 `Close` | 한국 종가는 원래 수정주가 ✓ |

세 소스가 같은 성질로 맞춰집니다. 그래서 **보유 수량에 분할 비율을 또 곱하면 안 됩니다.**
이미 가격에 반영돼 있습니다. 분할 데이터는 검증·표시용으로만 받습니다.

⚠ **Alpaca 에서 `adjustment=all` 을 쓰면 안 됩니다.** 배당까지 가격에 반영돼서,
분배금을 따로 더하는 구조에서는 **분배금이 이중 계산**됩니다.
실측: NVDA 2024-06-03 종가 — raw `1149.99` / split `115.00` / **all `114.67`**.
저 0.33달러 차이가 조용히 수익률을 부풀립니다.

DataFrame 규약도 못 박아두세요. 이걸 문서화 안 하면 provider 마다 모양이 달라집니다.

```
index : DatetimeIndex (tz 제거, 날짜만), 이름 "date"
열    : "close"      매수·평가에 쓰는 종가
        "adj_close"  조정종가(참고용, 없을 수 있음)
attrs : df.attrs["currency"], df.attrs["source"]
```

## 2. 미국 — Alpaca Market Data API

### 2-1. 왜 yfinance 만 쓰지 않는가

yfinance 는 **공식 API 가 아닙니다.** Yahoo 를 긁는 방식이라 **서버 IP 기준으로 차단**됩니다.
내 PC 에서 혼자 쓸 땐 멀쩡한데, **배포해서 여러 명이 동시에 들어오면 한 IP 에 요청이 몰려
통째로 막힙니다.** 그러면 앱의 모든 숫자가 한꺼번에 비어버립니다.

Alpaca 는 **API 키 기준 할당량**이라 이 문제가 없습니다. 그래서 사람이 많이 쓰는 경로일수록
Alpaca 를 앞에 둡니다.

### 2-2. 키 발급과 설정

1. alpaca.markets 가입 → **Paper Trading 계정이면 충분합니다**(주문 안 넣고 데이터만 씁니다).
2. API Key / Secret 발급.
3. `.streamlit/secrets.toml` 에 넣습니다. **이 파일은 절대 git 에 올리지 않습니다.**

```toml
ALPACA_API_KEY = "..."
ALPACA_SECRET_KEY = "..."
```

코드에서는 **Streamlit secrets → 환경변수** 순으로 찾습니다. 키가 없으면 Alpaca 를 아예
안 쓰고 yfinance 단독으로 동작합니다(개인 PC 에서 키 없이도 돌아가야 하니까).

```python
def credentials() -> tuple[str, str] | None:
    key = secret = ""
    try:
        import streamlit as st      # import 를 함수 안에 두어 Streamlit 의존을 약하게
        key = str(st.secrets.get("ALPACA_API_KEY", "") or "")
        secret = str(st.secrets.get("ALPACA_SECRET_KEY", "") or "")
    except Exception:
        pass
    if not (key and secret):
        key = os.environ.get("ALPACA_API_KEY", "")
        secret = os.environ.get("ALPACA_SECRET_KEY", "")
    return (key, secret) if (key and secret) else None
```

인증은 헤더 두 줄이 전부입니다. OAuth 같은 거 없습니다.

```python
{"APCA-API-KEY-ID": key, "APCA-API-SECRET-KEY": secret}
```

베이스 URL `https://data.alpaca.markets` · 무료 피드 `feed=iex` · 타임아웃 30초.

### 2-3. 엔드포인트별 실전 사용법

#### (a) 최신가 — `GET /v2/stocks/{symbol}/trades/latest?feed=iex`

```json
{"trade": {"p": 34.13, "t": "2026-09-15T19:59:58.123Z", "s": 100}}
```

`p` 가 가격, `t` 가 체결시각. 날짜만 남겨서 `as_of` 로 씁니다.

⚠ 무료 티어는 **IEX 거래소 체결** 기준이라 통합시세(SIP)와 소수점 단위 차이가 납니다.
"몇 주 살 수 있나"를 계산하는 데는 문제없지만, **공식 종가라고 표시하면 안 됩니다.**

#### (b) 일봉 — `GET /v2/stocks/{symbol}/bars`

```python
params = {
    "timeframe": "1Day",
    "start": start.isoformat(),      # "2021-01-04"
    "end": end.isoformat(),
    "adjustment": "split",           # ⚠ 반드시 split. all 금지 (§1-3)
    "feed": "iex",
    "limit": 10000,
}
```

응답: `{"bars": [{"t":"...","o":..,"h":..,"l":..,"c":..,"v":..}], "next_page_token": null}`
→ `c` 가 종가입니다.

**페이징**: `next_page_token` 이 있으면 `page_token` 파라미터로 다시 요청합니다.
`limit=10000` 이면 5년치 일봉(약 1,429건)은 한 페이지에 다 옵니다. 그래도 **페이징은 구현해두세요.**
안전장치로 최대 20페이지에서 끊습니다(무한 루프 방지).

⚠ **Alpaca 의 과거 데이터는 대략 2020년 중반까지밖에 없습니다.** 오래된 백테스트를
Alpaca 로 하면 막힙니다. → §3의 역할 분담이 이것 때문에 존재합니다.

#### (c) 분배금 — `GET /v1/corporate-actions?types=cash_dividend`

```json
{"corporate_actions": {"cash_dividends": [
  {"symbol":"SCHD","ex_date":"2026-06-25","rate":0.2645,"process_date":"2026-07-10"}
]}}
```

무료 티어에서도 나옵니다. 실측 확인: SCHD 분기 4건, JEPQ 월 13건 정상 수신.

**`ex_date`(배당락일) 기준으로 색인**하세요. yfinance `.dividends` 의 인덱스와 같은 기준이라
두 소스를 섞어도 어긋나지 않습니다.

> ### ⚠⚠ 이 문서에서 제일 중요한 함정
>
> **Alpaca 의 `start`/`end` 는 `ex_date` 가 아니라 `process_date`(처리일) 로 거릅니다.**
>
> 예: 리얼티인컴(O)의 `ex_date` 2026-08-31 배당은 `process_date` 가 2026-09-15 입니다.
> `end=오늘(9/12)` 로 조회하면 **이 배당이 응답에 안 들어옵니다.**
>
> 그대로 두면 **월배당 종목은 가장 최근 1건이 매번 누락**되어 분배금이 항상 낮게 나옵니다.
> 에러도 안 납니다. 그냥 조용히 12분의 1만큼 적게 나옵니다. 이런 게 제일 무섭습니다.
>
> **해법: 조회 구간을 미래로 넉넉히 늘려 받고, `ex_date` 기준 자르기는 우리가 직접 합니다.**
>
> ```python
> wide_start = min(start, date.today() - timedelta(days=365 * 6))
> wide_end   = max(end, date.today()) + timedelta(days=120)   # ← 미래로 120일 여유
> # ... wide 구간으로 받아 캐시 ...
> mask = (alls.index >= pd.Timestamp(start)) & (alls.index <= pd.Timestamp(end))
> return alls.loc[mask]
> ```
>
> 분할도 같은 이유로 앞뒤(−30일 / +120일)를 넉넉히 잡습니다.

#### (d) 분할 — `GET /v1/corporate-actions?types=forward_split,reverse_split`

```json
{"forward_splits": [{"symbol":"NVDA","ex_date":"2024-06-10","new_rate":10,"old_rate":1}]}
```

**비율 = `new_rate / old_rate`** (10:1 분할이면 10.0).
정분할·역분할을 **콤마로 한 번에 요청**하세요. 요청 수가 절반이 되고 중복 위험도 없습니다.

#### (e) HTTP 상태코드 → 전부 한국어 메시지로 바꿔서 던집니다

| 코드 | 실제 의미 | 사용자에게 |
|---|---|---|
| 400 | Alpaca 에 없는 심볼 (**한국 종목 넣으면 여기**) | "Alpaca 에 없는 종목입니다" |
| 401 / 403 | 키 오류 | "Alpaca 인증 실패 — API 키를 확인하세요" |
| 429 | 한도 초과 | "요청 한도를 초과했습니다. 잠시 후 다시 시도하세요" |
| 그 외 | — | "Alpaca 오류 (HTTP {code})" |

응답이 JSON 이 아닐 때(`ValueError`)도 잡아서 `DataUnavailable` 로 바꿉니다.
**네트워크 예외(`requests.RequestException`)도 마찬가지입니다.** 위층에는 `DataUnavailable`
한 종류만 올라가야 폴백이 깔끔합니다.

## 3. 미국 — Alpaca 와 yfinance 를 섞는 방법 (핵심 기술)

두 소스의 장단점이 **정확히 반대**입니다.

| | Alpaca (무료) | yfinance |
|---|---|---|
| 요청 한도 | **API 키 기준** (여러 명이 써도 안전) | **서버 IP 기준** (배포 시 막힘) |
| 과거 깊이 | 약 2020년 중반까지 | **10년 이상** |
| 분배금 | 있음 | 있음 |
| 공식성 | 공식 API | 비공식(스크래핑) |

그래서 **"어느 게 더 좋은가"를 고르지 않습니다. 호출 성격별로 나눠 씁니다.**

```
· 최신가, 분배금      → Alpaca 우선
    화면을 그릴 때마다 종목 수만큼 나가는 잦은 호출.
    여기가 막히면 앱의 핵심 숫자가 통째로 빔 → 한도에 강한 쪽을 씀.

· 가격 히스토리, 분할 → yfinance 우선
    백테스트에서만 쓰는 드문 호출. 대신 과거가 깊어야 함.
    Alpaca 를 먼저 쓰면 2020년 이전 백테스트가 막힘.
```

구현은 **방향만 다른 폴백 체인 두 개**입니다. 놀랄 만큼 간단합니다.

```python
class USCompositeProvider(MarketDataProvider):
    def __init__(self, alpaca, yahoo):
        self._live    = FallbackProvider(alpaca, yahoo)   # 잦은 호출: Alpaca 먼저
        self._history = FallbackProvider(yahoo, alpaca)   # 깊은 과거: yfinance 먼저

    def get_latest_price(self, t):        return self._live.get_latest_price(t)
    def get_distributions(self, t, s, e): return self._live.get_distributions(t, s, e)
    def get_price_history(self, t, s, e): return self._history.get_price_history(t, s, e)
    def get_splits(self, t, s, e):        return self._history.get_splits(t, s, e)
```

`FallbackProvider` 는 더 간단합니다. **`DataUnavailable` 일 때만** 2순위로 넘깁니다.
다른 예외는 진짜 버그이므로 숨기지 않고 터뜨립니다 — 이 구분이 중요합니다.

```python
def _try(self, method, *args):
    try:
        return getattr(self.primary, method)(*args)
    except DataUnavailable:
        return getattr(self.secondary, method)(*args)
```

**결과: 한 소스가 통째로 막혀도 앱은 계속 돕니다.** 그리고 어느 쪽에서 온 값인지는
`PriceQuote.source` / `df.attrs["source"]` 에 그대로 남아 **화면에 표시됩니다. 출처를 속이지 않습니다.**

## 4. 미국 — yfinance 사용법

검증 버전 **yfinance 1.6.0** (2026-09 실행 확인).

```python
t = yf.Ticker("SCHD")
raw = t.history(start="2021-01-04",
                end=(end + timedelta(days=1)).isoformat(),   # ⚠ end 는 배타적!
                auto_adjust=False,                           # ⚠ Close / Adj Close 분리
                actions=True)
# columns: Open High Low Close "Adj Close" Volume Dividends "Stock Splits" "Capital Gains"
```

⚠ **함정 셋. 전부 조용히 틀리는 종류입니다.**

1. **`end` 가 배타적(exclusive)** 입니다. 그날을 포함하려면 **하루를 더해야** 합니다.
   안 더하면 마지막 하루가 소리 없이 빠집니다.
2. **인덱스가 tz-aware(America/New_York)** 입니다. 한국 데이터와 합치면 인덱스가 안 맞아
   교집합이 비어버립니다. **날짜만 남겨 tz 를 죽이세요.**
   ```python
   pd.DatetimeIndex(pd.to_datetime([d.date() for d in idx]), name="date")
   ```
3. **장중에는 마지막 행 `Close` 가 NaN** 일 수 있습니다. `dropna(subset=["Close"])` 필수.

분배금·분할은 별도 속성이고 **기간 지정이 없습니다. 전체가 옵니다.**

```python
yf.Ticker("SCHD").dividends   # Series, index=ex_date(tz-aware), 전체 이력
yf.Ticker("NVDA").splits      # Series, 전체 이력
```

→ 이 "전체가 온다"는 성질이 §7-2 캐시 설계의 근거입니다. **공짜로 얻은 성질이니 꼭 활용하세요.**

`fast_info`(lastPrice, currency, yearHigh, yearLow)는 부가 정보용인데
**실패해도 무시하고 빈 dict 를 돌려줍니다.** 핵심 계산에 안 쓰기 때문입니다.
부가 정보 때문에 화면이 죽으면 안 됩니다.

## 5. 한국 — FinanceDataReader + yfinance 하이브리드

검증 버전 **finance-datareader 0.9.202**.

### 5-1. 가격은 FinanceDataReader

```python
raw = fdr.DataReader("005930", "2021-01-04", "2026-09-16")
# columns: Open High Low Close Volume Change   ← Adj Close 열이 없음
```

- **한국 종가는 원래 수정주가**(액면분할 반영)입니다. 그래서 분할 재조정이 필요 없습니다.
- `Close > 0` 필터를 꼭 넣으세요. 거래정지 등으로 0 이 들어오는 행이 있습니다.
- 티커는 **6자리 문자열**입니다. `zfill(6)` 로 앞의 0 을 살리세요.
  `005930` 을 정수로 다루면 `5930` 이 되어 조회가 실패합니다. 이거 진짜 많이 당합니다.

### 5-2. 분배금이 없습니다 → yfinance 한국 심볼로 우회

**FinanceDataReader 는 한국 종목의 분배금 시계열을 제공하지 않습니다.** 이게 한국 데이터의
가장 큰 구멍입니다. 우회로는 yfinance 의 한국 심볼입니다.

```python
def _yf_symbols(ticker: str) -> list[str]:
    t = str(ticker).strip()
    if len(t) == 6:                      # ⚠ isdigit() 로 거르지 말 것 (아래 참고)
        return [f"{t}.KS", f"{t}.KQ"]    # 코스피 / 코스닥
    return [t]
```

`.KS`(코스피) → `.KQ`(코스닥) 순으로 시도하고, 데이터가 나오는 쪽을 씁니다.

> ⚠ **실제로 당한 버그**: 처음엔 `t.isdigit()` 으로 걸렀습니다. 그런데 KRX 코드는 순수 숫자만
> 있는 게 아닙니다. ETN 등 일부 상품은 **숫자+영문 조합**입니다(예: `0219E0`).
> `isdigit()` 이 False 라 접미사를 안 붙였고, 그 종목들은 분배금 조회가 전부 실패했습니다.
> 확인해보니 `0219E0.KS` 에는 배당 데이터가 **있었습니다.**
> **길이가 6이면 숫자든 영문이든 접미사를 붙이세요.**

그래도 없으면? **지어내지 않습니다.** `DataUnavailable` 을 던지되 **메시지에 해결책을 담습니다.**

```
"[329200] 한국 종목의 분배금 데이터를 자동으로 확인할 수 없습니다.
 상세 패널에서 '직접 입력' 을 사용하세요."
```

그리고 UI 에 **"최근 12개월 주당 분배금 직접 입력"** 을 제공합니다.
이게 한국 ETF 를 다루는 현실적인 마지막 수단입니다.

> ⚠ **직접 입력값의 한계를 반드시 기억하세요.** 직접 입력은 "최근 12개월 합계" **숫자 하나**입니다.
> 언제 얼마씩 줬는지는 없습니다. 그래서 **현재 화면 계산에는 쓸 수 있어도, 과거 구간을 훑는
> 백테스트에는 펼쳐 쓸 수 없습니다.** 억지로 12로 나눠 매달 뿌리면 그건 데이터를 지어내는 겁니다.
> 백테스트에서는 제외하고, **제외했다고 화면에 말하세요.**
> ("분배금 데이터가 없어 제외" 라고 하면 안 됩니다. 사용자는 데이터를 **넣었으니까요.**
> "입력값은 한 숫자라 과거 구간에 펼칠 수 없어 뺐습니다" 가 정확한 말입니다.)

### 5-3. 한국 분할

yfinance 한국 심볼로 시도하고, 없으면 **빈 Series 를 정상으로 간주**합니다.

## 6. 환율 — 백테스트 정확도의 절반

> **가장 중요한 원칙: 과거 백테스트에는 "과거 주가 + 과거 환율" 을 쓴다.
> "과거 주가 + 현재 환율" 을 절대 쓰지 않는다.**

원/달러가 1,100원에서 1,360원으로 움직이면 **환율만으로 수익률이 20% 넘게 왜곡**됩니다.
미국 주식을 원화로 보여주는 서비스에서 이걸 틀리면 나머지가 아무리 정확해도 의미가 없습니다.

```python
get_latest_rate()   -> FxQuote      # 현재 포트폴리오용
get_rate_on(d)      -> FxQuote      # 백테스트용: d "이전" 가장 가까운 거래일 환율
get_history(s, e)   -> Series       # 구간 시계열
```

- 1순위 yfinance `"USDKRW=X"` → 2순위 FinanceDataReader `"USD/KRW"`.
  둘 다 실패하면 `DataUnavailable` (추정 금지).
- ⚠ **주말·공휴일 처리**: 매수일이 거래일이 아닐 수 있습니다. `d` 의 환율이 없으면
  **`d` 이전 가장 가까운 거래일** 값을 씁니다. 뒤로 가면 **미래 정보를 쓰는 셈이라 반칙**입니다.
  조회는 `d-14일 ~ d+1일` 로 여유 있게 받아 그중 `<= d` 의 마지막 값을 고릅니다.

```python
s = get_history(d - timedelta(days=14), d + timedelta(days=1))
on_or_before = s.loc[s.index <= pd.Timestamp(d)]
if on_or_before.empty:
    raise DataUnavailable(f"{d} 또는 그 이전의 USD/KRW 환율 데이터를 가져올 수 없습니다.")
rate = float(on_or_before.loc[on_or_before.index.max()])
```

## 7. 캐시 — "최저 비용"의 정체

무료 티어로 버티는 비결의 90%가 여기 있습니다. 캐시 본체는 20줄짜리로 아주 단순합니다.
**중요한 건 코드가 아니라 키를 어떻게 설계하느냐입니다.**

### 7-1. 캐시 본체

```python
_STORE: dict[str, tuple[float, Any]] = {}     # 프로세스 전역

def get_or_set(key: str, ttl_seconds: int, producer: Callable[[], Any]) -> Any:
    now = time.time()
    hit = _STORE.get(key)
    if hit is not None and (now - hit[0]) < ttl_seconds:
        return hit[1]
    value = producer()          # ⚠ 예외가 나면 저장하지 않고 그대로 전파
    _STORE[key] = (now, value)
    return value
```

핵심 성질 셋:

1. **프로세스 전역**입니다. Streamlit 에서는 **모든 접속자가 같은 캐시를 공유**합니다.
   먼저 들어온 사람이 SCHD 를 조회해두면 다음 사람은 호출이 안 나갑니다.
   **사용자가 늘어도 API 호출은 거의 안 늘어납니다.** 이게 무료로 서비스가 되는 진짜 이유입니다.
2. **실패는 절대 캐싱하지 않습니다.** 예외가 나면 저장 없이 그대로 던집니다.
   실패를 캐싱하면 "다시 시도" 버튼이 무력해집니다.
3. **디스크를 안 씁니다.** 무료 호스팅은 파일 쓰기 권한이 없거나 재시작 때 날아갑니다.
   메모리만으로 충분합니다.

`invalidate(prefix=None)` 로 전체/접두사 단위 무효화 → **"데이터 업데이트" 버튼**이 이걸 씁니다.

### 7-2. ⚠ 키 설계 — 여기가 진짜 기술입니다

**원칙: 기간이 달라도 같은 데이터면 같은 키를 쓴다. 즉 "전체를 받아 캐시하고, 잘라서 준다."**

```python
# ❌ 나쁜 예 — 기간이 키에 들어감
key = f"us:div:{ticker}:{start}:{end}"
#   화면(최근 12개월)과 백테스트(5.7년)가 서로 다른 키 → 같은 종목인데 호출 2번

# ✅ 좋은 예 — 기간이 키에 없음
key = f"us:div:{ticker}"
def _load_all():
    return yf.Ticker(ticker).dividends       # 어차피 전체가 옴 (§4)
alls = cache.get_or_set(key, TTL, _load_all)
mask = (alls.index >= pd.Timestamp(start)) & (alls.index <= pd.Timestamp(end))
return alls.loc[mask]                        # 자르기는 메모리에서
```

**효과가 큽니다.** 화면에서 이미 분배금을 조회한 종목은 백테스트가 5년치를 요구해도
**네트워크 호출이 0번**입니다. 같은 캐시 한 칸을 씁니다.

실제 키 목록:

| 키 | 기간 포함? | 이유 |
|---|---|---|
| `us:div:{ticker}` | ❌ | yfinance 가 전체를 주므로 전체 캐시 후 자르기 |
| `kr:div:{ticker}` | ❌ | 〃 |
| `us:split:{ticker}` | ❌ | 〃 |
| `alpaca:div:{ticker}:{wide_start}:{wide_end}` | 🔸 **넓힌** 구간 | Alpaca 는 기간 필수 → **과거 6년 + 미래 120일**로 넓혀 적중률을 올림 |
| `us:hist:{ticker}:{start}:{end}` | ✅ | 히스토리는 구간이 진짜 다름. 백테스트에서만 쓰는 드문 호출이라 괜찮음 |
| `fx:usdkrw:on:{d}` | ✅ | 날짜별 한 칸. 가벼움 |

Alpaca 분배금 키를 넓히는 게 중요합니다. 시작일이 **6년 이내면 wide 구간이 항상 같아져서**
백테스트 기간을 바꿔도 캐시가 계속 맞습니다. 6년보다 오래된 백테스트만 새 호출이 나갑니다.

### 7-3. TTL — 근거 없이 길게 잡지 않습니다

| 데이터 | TTL | 근거 |
|---|---|---|
| 최신가 | **15분** | 실시간일 필요 없음. 포트폴리오 구성용 |
| 가격 히스토리 | **6시간** | 과거 데이터는 안 변함 |
| 환율 | **1시간** | 하루 안에서 크게 안 움직임 |
| 분배금 | **12시간** | 분기·월 단위 이벤트. 하루 두 번이면 충분 |
| 종목 검색 목록 | **24시간** | 상장/폐지는 드묾. 목록이 제일 무거움 |

### 7-4. 실제 호출 횟수 (5종목 포트폴리오)

| 상황 | 호출 수 |
|---|---|
| 첫 접속 (캐시 빔) | 최신가 5 + 분배금 5 + 환율 1 = **11회** |
| 15분 내 재접속·다른 사람 접속 | **0회** |
| 15분 후 (최신가만 만료) | **5회** |
| 백테스트 실행 (5.7년) | 히스토리 5 + 환율 1 ≈ **6회**. **분배금 0회** (§7-2 덕분) |

무료 티어 한도에 한참 못 미칩니다.

## 8. 실패·경계 상황 처리 (이거 안 하면 실서비스에서 터집니다)

| 상황 | 처리 |
|---|---|
| 라이브러리 import 실패 | 모듈 로드 시 `try/except` 로 `None` 저장 → 호출 시점에 `DataUnavailable("pip install ... 확인하세요")` |
| 한 소스만 다운 | `FallbackProvider` 가 자동으로 반대편으로 (§3) |
| 종목이 아예 없음 | `DataUnavailable` → 화면에 "데이터 없음". 0으로 채우지 않음 |
| 상장 12개월 미만 | TTM 이 성립 안 함. **지급 2회 이상이면** 관측일수→365일 연환산 + **"추정치"라고 표시**. 0~1회면 연환산 금지(근거 부족) |
| 상장일을 모름 | 젊은 종목 예외 로직을 **아예 안 탐**. "모르는 것"을 "젊다"고 단정하지 않음 |
| 장중 마지막 봉 NaN | `dropna(subset=["Close"])` |
| 거래정지로 종가 0 | `Close > 0` 필터 |
| 매수일이 휴일 | 환율·가격 모두 **이전** 거래일로 (미래 참조 금지) |
| 응답이 JSON 이 아님 | `ValueError` 잡아서 `DataUnavailable` 로 변환 |
| 무한 페이징 | 최대 20페이지에서 강제 종료 |

연환산 추정의 실제 모양 — **근거를 문장에 그대로 남깁니다.**

```
⚠ 추정치: 상장(데이터 시작) 후 약 7.3개월, 아직 만 12개월이 되지 않았습니다.
실제 지급 6회 합계 0.8412 USD(관측 기간 223일)를 365일 기준으로 연환산한 값입니다.
실제 향후 분배금과 다를 수 있습니다.
```

## 10. 마지막으로 — 이 구조가 지키려는 것

기술만 보면 이건 "API 몇 개 호출해서 pandas 로 정리하는 코드"입니다.
하지만 실제로 중요한 건 다음 세 가지고, 이건 코드보다 **태도**에 가깝습니다.

1. **모르면 모른다고 말한다.** 금융 데이터는 틀려도 그럴듯해 보입니다. 사용자는 검산할 수
   없습니다. 빈칸을 그럴듯한 숫자로 메우는 순간, 그 서비스는 거짓말을 하는 서비스가 됩니다.
2. **한 소스에 목숨을 걸지 않는다.** 무료 소스는 언제든 막히고, 없어지고, 유료화됩니다.
   인터페이스 뒤에 숨겨두면 그날이 와도 파일 하나만 갈아끼우면 됩니다.
3. **출처를 속이지 않는다.** IEX 값을 통합시세인 척하지 않고, 추정치를 실측인 척하지 않습니다.
   화면에 "이 숫자는 어디서 왔는가"를 항상 같이 적습니다.

이 셋만 지키면 소스가 무엇으로 바뀌든 이 구조는 계속 씁니다.

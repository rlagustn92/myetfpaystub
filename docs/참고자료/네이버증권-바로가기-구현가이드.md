# 네이버(Npay) 증권 종목 페이지 바로가기 — 구현 가이드

다른 서비스에 그대로 옮겨 붙이라고 쓴 문서다. 이 프로젝트에 대한 사전 지식이 없어도
되고, 코드는 **파이썬 표준 라이브러리만** 쓴다. 2026-09-20 실측 기준이다.

> 읽는 사람이 AI 라면: 아래 **3분 요약**만 보고 바로 구현해도 된다.
> 그 아래는 "왜 그렇게 해야 하는지" 와 "직접 해보면 밟게 될 함정" 이다.

## 3분 요약

종목 상세 화면에 "네이버 증권에서 보기" 링크를 다는 일이다.

**국내는 주소를 직접 만들 수 있다.**

```
https://m.stock.naver.com/domestic/stock/{6자리코드}/total
예) https://m.stock.naver.com/domestic/stock/069500/total
```

**미국은 만들 수 없다.** 티커 뒤에 붙는 거래소 표시가 종목마다 다르다.

```
TQQQ  →  /worldstock/etf/TQQQ.O
SCHD  →  /worldstock/etf/SCHD.K
VOO   →  /worldstock/etf/VOO        ← 아무것도 안 붙는다
TSLA  →  /worldstock/stock/TSLA.O/total   ← ETF 와 경로도 다르다
```

**네이버 자동완성에 물어보면 주소를 그대로 준다.**

```
GET https://ac.stock.naver.com/ac?q=SCHD&target=stock
→ {"items":[{"code":"SCHD","name":"Schwab US Dividend Equity ETF",
             "url":"/worldstock/etf/SCHD.K","nationCode":"USA", ...}]}
```

`https://m.stock.naver.com` + `url` 이 최종 주소다.

**호출은 수집·배치에서만 하고 결과를 저장해 둔다.** 사용자가 검색할 때마다 부르면 안 된다.

```python
import json, urllib.parse, urllib.request

BASE = "https://m.stock.naver.com"
HEADERS = {"User-Agent": "Mozilla/5.0", "Referer": "https://m.stock.naver.com/"}

def korean_url(code: str) -> str:
    return f"{BASE}/domestic/stock/{code}/total"

def lookup(ticker: str, nation: str = "USA") -> str | None:
    q = urllib.parse.urlencode({"q": ticker, "target": "stock"})
    req = urllib.request.Request(f"https://ac.stock.naver.com/ac?{q}", headers=HEADERS)
    try:
        with urllib.request.urlopen(req, timeout=8) as r:
            data = json.loads(r.read().decode("utf-8"))
    except Exception:
        return None                      # 실패하면 링크를 안 그린다. 추측하지 않는다
    want = ticker.strip().upper()
    for item in data.get("items") or []:
        if (str(item.get("code", "")).upper() == want
                and item.get("nationCode") == nation
                and item.get("url")):
            return BASE + str(item["url"])
    return None
```

이게 전부다. 나머지는 규모가 커졌을 때의 이야기다.

## 1. 왜 주소를 만들 수 없나 — 직접 확인한 것

"거래소별로 접미사가 정해져 있겠지" 라고 생각하고 규칙을 세워 봤는데 **없다.**

| 티커 | 네이버가 말하는 거래소 | 실제 주소 |
|---|---|---|
| SCHD | AMEX | `/worldstock/etf/SCHD.K` |
| VOO | **AMEX (같음)** | `/worldstock/etf/VOO` |
| TQQQ | NASDAQ | `/worldstock/etf/TQQQ.O` |
| JEPI | AMEX | `/worldstock/etf/JEPI.K` |
| SPY | AMEX | `/worldstock/etf/SPY` |

SCHD 와 VOO 는 네이버 기준 **같은 거래소인데 한쪽만 `.K` 가 붙는다.**
`SPY.K` 는 빈 페이지가 나오고 `SPY` 는 열린다. 반대로 `TQQQ` 는 빈 페이지고 `TQQQ.O` 가 열린다.

**추측해서 만들면 상당수가 빈 페이지로 간다.** 물어보는 것 말고 방법이 없다.

## 2. 자동완성 엔드포인트 명세 (실측)

```
GET https://ac.stock.naver.com/ac?q={검색어}&target=stock
```

응답 예시 (필요한 필드만):

```json
{"query": "SCHD",
 "items": [{"code": "SCHD",
            "name": "Schwab US Dividend Equity ETF",
            "url": "/worldstock/etf/SCHD.K",
            "reutersCode": "SCHD.K",
            "typeCode": "AMEX",
            "typeName": "아멕스 증권거래소",
            "nationCode": "USA",
            "nationName": "미국",
            "category": "stock"}]}
```

확인한 사실 몇 가지.

- **헤더는 필수가 아니다.** User-Agent·Referer 를 둘 다 빼도 응답했다.
  그래도 붙이기를 권한다 — 남의 서버를 수천 번 두드리면서 신원을 안 밝히는 것은
  예의가 아니고, 저쪽이 언제든 요구하도록 바꿀 수 있다.
- **국내도 같은 창구로 나온다.** `q=005930` → `/domestic/stock/005930/total`.
  다만 국내는 코드로 조립되므로 굳이 부를 필요가 없다.
- **ETF 와 일반주식은 경로가 다르다.** ETF 는 `/worldstock/etf/...`(끝에 `/total` 없음),
  주식은 `/worldstock/stock/.../total`. **직접 조립하지 말고 돌려준 `url` 을 그대로 써라.**
- 비슷한 이름이 같이 온다. 반드시 `code` 완전일치 + `nationCode` 로 걸러라.
  안 그러면 "SCHD" 를 물었는데 이름이 비슷한 다른 나라 종목이 잡힌다.

> 공식 문서가 있는 API 가 아니다. 언제든 바뀔 수 있다는 전제로 쓰고,
> 실패하면 링크를 **안 그리는** 쪽으로 설계하라. 빈 페이지로 보내는 것보다 낫다.

## 3. 종목이 수천 개라면 — 여기서 한 번 크게 데였다

내 PC 에서는 **1건에 0.06초**였다. 5,693종목이 5분. "그냥 배치에서 매번 돌리면 되겠네" 하고
GitHub Actions 러너에 올렸더니 **38분이 지나도 그 단계를 못 빠져나왔다.**
같은 조건의 직전 배치는 11분에 끝났고, 달라진 건 이 호출뿐이었다.

클라우드 IP 라 조이는 것으로 보인다. (완전히 막는 건 아니다 — 나중에 13건짜리 소량
호출은 러너에서도 성공했다. 대량일 때 느려지는 쪽에 가깝다.)

**해법은 결과를 저장소에 넣어두는 것이다.**

```
1. 개발자 PC 에서 한 번 전부 받아 CSV 로 저장 → 저장소에 커밋
2. 배치는 그 CSV 를 먼저 깔고, 거기 없는 종목만 물어본다
3. 결과: 러너에서 38분 → 7.9초 (시드 5,693건 + 신규 13건만 호출)
```

CSV 는 `code,naver_url` 두 칸이면 되고 5,700종목에 300KB 다.

### 배치에 반드시 걸어야 할 안전장치 셋

이 단계는 **있으면 좋은 것이지 서비스의 본질이 아니다.** 그런데 그대로 두면
이 단계 하나가 하루치 갱신을 통째로 날린다. 셋을 건다.

```python
BUDGET_SECONDS = 8 * 60   # 1) 시간 예산: 지나면 남은 건 다음 실행으로
FAIL_STREAK    = 30       # 2) 회로차단기: 연달아 실패하면 상대가 막는 것으로 보고 중단
CHUNK          = 300      # 3) 중간 저장: 300건마다 DB 에 쓴다
```

**3번이 제일 중요하다.** 처음엔 전부 모았다가 마지막에 한 번 저장하게 짰는데,
38분을 쓰고 중간에 끊기니 **한 건도 안 남았다.** 다음 실행이 또 처음부터 부른다 —
상대 서버에도 우리에게도 최악이다.

```python
import time

def resolve_missing(todo, save_chunk):
    started, found, streak, rows = time.time(), 0, 0, []
    for ticker in todo:
        if time.time() - started > BUDGET_SECONDS:
            break                                   # 다음 실행에서 이어받는다
        url = lookup(ticker)
        if url:
            rows.append((ticker, url)); found += 1; streak = 0
        else:
            streak += 1
            if streak >= FAIL_STREAK:
                break                               # 막힌 것으로 본다
        if len(rows) >= CHUNK:
            save_chunk(rows); rows = []
    if rows:
        save_chunk(rows)
    return found
```

시드를 다시 만드는 스크립트에는 **줄어들면 덮어쓰지 않는** 장치를 넣어라.
네트워크가 반쯤 죽은 상태로 돌려서 멀쩡한 시드를 날리는 사고를 막는다.

```python
if before and len(new) < before * 0.8:
    print("새 시드가 너무 줄었습니다. 덮어쓰지 않습니다."); return 1
```

## 4. 제대로 들어갔는지 확인하는 법

주소가 200 을 준다고 맞는 게 아니다. **네이버는 없는 종목에도 200 을 준다**(SPA 라서).
`<title>` 로 판정하라.

```python
import re, urllib.request

def verify(url: str) -> str:
    req = urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0"})
    html = urllib.request.urlopen(req, timeout=15).read().decode("utf-8", "replace")
    m = re.search(r"<title>(.*?)</title>", html, re.S)
    return m.group(1).strip() if m else ""

# 맞으면: "Schwab US Dividend Equity ETF - Npay 증권"
# 틀리면: "Npay 증권"        ← 종목명이 없다 = 그 주소에 종목이 없다
```

나는 전체를 채운 뒤 **무작위 9건을 뽑아 이 방법으로 확인**했다(9/9 정확).
전수 검사는 남의 서버를 수천 번 더 두드리는 일이라 하지 않았다.

## 5. 앱으로 넘기는 것은 **안 된다** (확인함)

"모바일에서는 네이버 앱(또는 토스 앱)으로 열리게 하자" 는 요구가 나올 것이다. 안 된다.

웹주소를 앱이 가로채려면 사이트가 아래 파일을 올려둬야 한다. **없다.**

```
m.stock.naver.com/.well-known/apple-app-site-association   →  404
m.stock.naver.com/.well-known/assetlinks.json              →  404
tossinvest.com/.well-known/apple-app-site-association      →  없음(웹페이지만 반환)
종목 페이지의 apple-itunes-app 배너                          →  없음
```

`naversearchapp://` `supertoss://` 같은 **커스텀 스킴은 쓰지 마라.**

- 공개 규격이 아니라 저쪽이 바꾸면 조용히 깨지고, 깨진 걸 알 방법이 없다
- 앱이 없는 사용자는 **빈 탭만** 보게 된다. 설치 여부를 알아낼 방법도 없다
- 웹앱이 iframe 안에서 돌면(예: Streamlit Cloud) 샌드박스에 막힐 수도 있다

**그냥 https 주소를 쓰는 게 최선이다.** 나중에 네이버·토스가 설정을 열면
**코드를 한 줄도 안 고쳐도** 그때부터 앱이 가로챈다.

### 그래도 모바일에서 네이버가 나은 이유

앱은 안 뜨지만 `m.stock.naver.com` 은 **원래 모바일용으로 만든 화면**이다.
PC 용 화면을 폰에서 억지로 보는 것과 체감이 다르다. 그리고 같은 주소가
PC 에서도 열린다 — 주소를 하나만 만들면 된다.

## 6. 화면에 붙일 때 (선택)

한 가지만 경고한다. 라벨을 길게 달지 마라.

`Npay증권(PC·모바일)` 로 달았더니 종목명이 38자만 넘어가도 칩이 **다음 줄로 밀렸다.**
바로가기는 종목명과 같은 줄에 있어야 눈에 들어온다.

```
Npay증권 ↗         ← 짧게
title="PC·모바일 모두 같은 주소로 열립니다"   ← 설명은 툴팁으로
```

칩이 셋 이상이면 글자 크기도 한 단계 줄여라(1rem → .9rem). 그것만으로
가장 긴 이름에서도 한 줄에 들어왔다.

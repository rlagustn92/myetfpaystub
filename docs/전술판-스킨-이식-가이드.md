# 전술판 스킨 시스템 이식 가이드

이미 축구 전술판(카드 + 유니폼 + 잔디)이 있는 앱에 **스킨(경기장 테마) 한 겹**을
얹는 방법입니다. MY ETF 급여명세서에서 실제로 돌아가고 있는 구현을 그대로
옮길 수 있게 정리했습니다.

- 대상: 전술판을 이미 만들어 둔 사람 (카드 배치·유니폼 그리기는 있다고 가정)
- 걸린 시간: 데이터 21벌 + 프론트엔드 + 테스트까지 하루
- 결과물: 스킨 하나 고르면 **잔디·깎기무늬·광고보드·관중석·유니폼·센터서클**이
  한 번에 바뀝니다. 📸 캡처 이미지도 저절로 같이 바뀝니다.

---

## 1. 한 장 요약

```
components/skins.py          스킨 21벌 — 순수 데이터 (색 문자열만)
      │  Skin.to_dict()
      ▼
services/skin_service.py     지금 이 사용자가 쓸 수 있는 스킨인가 / 골라서 저장
      │  skin=skin_now.to_dict()
      ▼
components/football_pitch/   전술판 컴포넌트 (순수 HTML/JS, 빌드 단계 없음)
      │  applySkin(sk)
      ▼
   :root 의 CSS 변수 한 벌  ──▶  화면(HTML/SVG)
                            └─▶  📸 캡처(Canvas) — 같은 변수를 읽어 그립니다
```

**핵심은 마지막 두 줄입니다.** 스킨 색을 **CSS 변수 한 벌로만** 넘기면,
화면과 캔버스가 같은 값을 읽으므로 한 곳만 고쳐도 둘이 저절로 같아집니다.
따로 칠하기 시작하면 "화면은 맞는데 공유한 이미지만 색이 다른" 버그가 납니다.

## 3. 데이터 모델

스킨 하나는 **색 문자열 묶음**입니다. 로직이 없습니다 — 그래서 스킨을 늘리는
일이 데이터 한 줄 추가로 끝납니다.

```python
@dataclass(frozen=True)
class Skin:
    id: str
    name: str            # "London Red Edition"
    korean: str          # "런던 레드 — 붉은 몸통에 흰 소매"

    # ---- 경기장 ----
    turf_a: str          # 잔디 두 톤
    turf_b: str
    mow: str             # bands | vertical | checks | diagonal
    line: str            # 흰 선
    slot: str            # 빈 자리 점선
    frame_a: str         # 광고보드 두 색
    frame_b: str
    stand: str           # 관중석(판 바깥) 배경
    accent: str          # 고른 카드 강조

    # ---- 유니폼 ----
    body: str = ""       # ⭐ 비우면 "브랜드 색"으로 그립니다 (§5-1)
    sleeve: str = ""
    trim: str = ""       # 깃
    pattern: str = "plain"   # plain|stripes|hoops|center|sash|pinstripe|diamonds
    pattern_color: str = ""
    shorts: str = ""     # ⭐ 하의는 §5-2
    socks: str = ""
    sock_band: str = ""

    # ---- 글자 / 센터서클 ----
    chant: str = ""       # 위 배너 (그 나라 말로)
    chant_home: str = ""  # 아래 배너
    badge: str = ""       # 센터서클 글자 — 지명 약자만
    badge_bars: tuple[str, ...] = ()   # 국기·지역기 색띠
    badge_dir: str = "v"  # v | h | cross | saltire | diamond

    tier: str = TIER_PREMIUM
```

실제 한 벌은 이렇게 생겼습니다.

```python
Skin("london-red", "London Red Edition", "런던 레드 — 붉은 몸통에 흰 소매",
     "#2E8B3E", "#2A8238", "bands",
     "rgba(255,255,255,0.82)", "rgba(255,255,255,0.45)",
     "#C8102E", "#FFFFFF", "#F4E3E5", "#E8C34A",
     body="#E30613", sleeve="#FFFFFF", trim="#E8C34A", pattern="plain",
```

### 파이썬 → 자바스크립트 경계

```python
def to_dict(self) -> dict:
    """⚠ 키 이름을 바꾸면 프론트엔드의 applySkin 이 **조용히** 못 읽습니다.
    에러가 안 나고 색만 기본값으로 남습니다. 테스트가 이 짝을 지킵니다."""
    return {
        "id": self.id, "name": self.name,
        "turfA": self.turf_a, "turfB": self.turf_b, "mow": self.mow,
        "line": self.line, "slot": self.slot,
        "frameA": self.frame_a, "frameB": self.frame_b,
        "stand": self.stand, "accent": self.accent,
        "body": self.body, "sleeve": self.sleeve, "trim": self.trim,
        "pattern": self.pattern,
        "patternColor": self.pattern_color or self.sleeve,
        "shorts": self.shorts, "socks": self.socks, "sockBand": self.sock_band,
        "chant": self.chant, "chantHome": self.chant_home,
        "badge": self.badge,
        "badgeBars": list(self.badge_bars), "badgeDir": self.badge_dir,
    }
```

snake_case → camelCase 로 바뀌는 지점이라 오타가 나기 제일 쉬운 곳입니다.
**테스트로 묶으세요** (§7).

## 4. 프론트엔드 — CSS 변수 한 벌

```js
function applySkin(sk) {
  if (!sk) return;
  const root = document.documentElement.style;
  const set = (k, v) => { if (v) root.setProperty(k, v); };
  set("--turf-a", sk.turfA);
  set("--turf-b", sk.turfB);
  set("--line",   sk.line);
  set("--slot",   sk.slot);
  set("--frame-a", sk.frameA);
  set("--frame-b", sk.frameB);
  set("--accent", sk.accent);
  set("--stand",  sk.stand);
  // 배너·배지는 아래 §5-3, §5-4
}
```

기존 CSS 에서 하드코딩된 색을 이 변수들로 바꾸기만 하면 경기장 쪽은 끝입니다.

```css
.pitch { background:
  repeating-linear-gradient(0deg, var(--turf-a) 0 28px, var(--turf-b) 28px 56px); }
.pitch .line  { background: var(--line); }
.pitch .slot  { border-color: var(--slot); }
```

캔버스(📸 캡처)에서는 같은 변수를 **읽어서** 씁니다.

```js
const css = getComputedStyle(document.documentElement);
const turfA = css.getPropertyValue("--turf-a").trim();
```

이렇게 해 두면 스킨을 하나 더 추가할 때 캔버스 코드는 **손댈 일이 없습니다.**

## 5. 반드시 이렇게 해야 하는 것 다섯 가지

전부 실제로 한 번 틀려 보고 고친 것들입니다.

### 5-1. 기본 스킨은 유니폼 몸통을 **안** 바꾼다

기본 상태에서 몸통 색은 **정보**입니다(우리 앱은 운용사 브랜드 색: KODEX 남색,
TIGER 주황 …). 아무 스킨도 안 고른 사람에게 그 정보가 사라지면 안 됩니다.

```js
function bodyOf(kit) {
  const sk = skin || {};
  if (sk.body) return sk.body;        // 클럽풍 스킨 = 팀 색
  return kit.main;                    // 기본 = 원래 정보 색
}
```

`body` 를 **빈 문자열로 두면 예전과 똑같이** 그려집니다. 기본값이 곧 "정보 우선"
모드입니다.

반대로 **클럽풍 스킨은 몸통까지 팀 색으로 칠해야 합니다.** 소매·깃·무늬만
물들여 봤는데 몸통 면적(유니폼의 70%)을 못 이겨서 팀이 전혀 안 떠올랐습니다
("마드리드인지 잘 모르겠다"는 실제 피드백). 몸통을 내주는 대신 원래 정보는
**세 곳**에 남겼습니다 — 이름표 배경 · 상의 테두리 · 가슴 두 글자.

### 5-2. 반바지·양말에 브랜드 색이 한 톨도 들어가면 안 된다

처음엔 테두리를 브랜드 색으로, 양말 띠를 몸통색에서 파생시켰더니 **카드마다
하의가 달라서** "축구팀 같지 않다"는 지적을 받았습니다. 상의-반바지-양말
3색 조합으로 팀을 알아보기 때문입니다.

- 하의 색은 `shorts` / `socks` / `sock_band` **세 필드에서만** 옵니다.
- 그 값은 **실제 그 팀 조합**을 적습니다. 소매 색에서 기계적으로 파생시키면
  조합이 엉터리가 되어 팀이 안 떠오릅니다.
- 테두리는 색이 아니라 **밝기**로 정합니다(`outlineFor(hex)`).

### 5-3. 배너 글자색은 스킨 색에서 고르지 말 것

두 번 틀렸습니다.

1. `accent` 를 글자색으로 썼더니, `accent` 와 광고보드 색이 같은 스킨 4벌에서
   글자가 아예 안 보였습니다.
2. 단순 밝기 문턱값(0.55)으로 흑/백을 골랐더니 중간 밝기에서 틀렸습니다
   (하늘색 `#12A0D7` + 흰 글자 → 대비 2.98, 안 읽힘).

지금은 문턱값을 안 쓰고 **흑·백 중 실제 대비가 더 높은 쪽**을 고릅니다.
어떤 색이 와도 최선이 나옵니다.

```js
function textOn(hex) {
  const L = relLum(hex);
  const white = 1.05 / (L + 0.05);
  const black = (L + 0.05) / (relLum("#111111") + 0.05);
  return white >= black ? "#FFFFFF" : "#111111";
}
```

배너 **바탕**도 줄무늬로 두면 안 됩니다. 밝은 칸 위에서 글자가 반쯤 묻힙니다.
두 광고보드 색 중 **어두운 쪽을 단색**으로 깔고, 나머지 한 색은 아래쪽 얇은
선으로 넣어 두 색이 다 보이게 했습니다.

### 5-4. 화면과 캔버스가 **같은 도형**을 그려야 한다

유니폼 무늬는 화면에선 SVG(`patternSVG`), 캡처에선 Canvas(`drawPattern`)로
그립니다. 좌표가 두 곳에 적혀 있으므로 **같이 고쳐야 합니다.**

```js
// 화면 (SVG 문자열)
function patternSVG(kind, color) {
  if (kind === "stripes")
    return '<rect x="8"  y="0" width="13" height="118" fill="' + color + '"/>' +
           '<rect x="43" y="0" width="13" height="118" fill="' + color + '"/>' +
           '<rect x="78" y="0" width="13" height="118" fill="' + color + '"/>';
  ...
}

// 캡처 (Canvas) — 좌표가 위와 같아야 합니다
function drawPattern(ctx, kind, color) {
  if (kind === "stripes") {
    ctx.fillStyle = color;
    for (const x of [8, 43, 78]) ctx.fillRect(x, 0, 13, 118);
  }
  ...
}
```

센터서클 깃발은 아예 **한 함수(`badgeParts(dir, bars)`)를 양쪽이 같이 쓰게**
해서 어긋날 수 없게 만들었습니다. 새로 만든다면 처음부터 이 방식을 권합니다.
잔디 깎기 무늬도 같은 짝(`applySkin` ↔ 캔버스의 `mow` 분기)입니다.

### 5-5. 무늬는 바탕이 **절반 이상** 남게

줄무늬를 촘촘하게 넣으면 몸통색이 안 보여서 팀이 안 떠오르고, 등번호도 안
읽힙니다. 그래서 세로줄은 3개, 가로줄도 3개까지만 넣었습니다.
등번호에는 **몸통색 후광(stroke)** 을 둘러야 줄무늬 위에서도 읽힙니다.

## 6. 저작권·상표 (이게 제일 중요합니다)

실제 구단을 흉내 내는 스킨이라 여기서 선을 분명히 그었습니다.

| 쓴 것 | 안 쓴 것 |
|---|---|
| 색 조합 (누구의 것도 아님) | 구단 이름·별칭 (`Gunners` 류 — 등록상표) |
| 지명 (`London`, `Madrid`) | 구단 약칭 (`LFC`, `PSG`, `BVB` — 상표) |
| 국기·지역기 색띠 (공공 상징) | 구단 엠블럼, **그리고 엠블럼을 연상시키는 도형** |
| 일반 응원어 (그 나라 말로) | 구단 공식 슬로건·응원가 제목 |

스킨 이름은 `London Red Edition` 처럼 **지명 + 색**으로만 짓습니다.
센터서클 배지는 **지명 약자**(`LDN`)에 국기 색띠를 깔았습니다.

도시 상징 도형(곰·벌·화산 …)도 시안으로 만들어 봤지만, 상표 위험 대비 효과가
낮아서 깃발로 정했습니다.

> 응원 배너는 **그 나라 말**로 적습니다. 영어 스킨 이름을 그대로 적었더니
> 팀이 전혀 연상되지 않았습니다. 그리고 위아래 **둘 다 응원 문구**여야 합니다 —
> 아래쪽에 서비스 이름을 적었더니 경기장 느낌이 깨졌습니다.

## 7. 테스트로 묶어 둔 것

색 문제는 **에러가 안 나고 눈으로 볼 때까지 모릅니다.** 그래서 규칙을 전부
테스트로 박아 뒀습니다. 스킨을 추가할 때 이 테스트들이 대신 검사해 줍니다.

- 모든 색 문자열이 진짜 색인가 (`#RGB`, `#RRGGBB`, `rgba(...)`)
- `mow` / `pattern` / `badge_dir` 이 **프론트엔드가 아는 값**인가
  (프론트엔드 소스를 읽어서 그 분기가 실제로 있는지 확인)
- `to_dict()` 의 키를 프론트엔드가 실제로 읽는가 (index.html 을 문자열 검색)
- 배너 글자 대비가 21벌 전부 **WCAG AA(4.5:1)** 이상인가
- 등번호·가슴 글자가 몸통색 위에서 읽히는가
- 하의 색에 브랜드 색이 안 섞였는가
- 몸통색과 무늬색이 같지 않은가 (같으면 무늬가 안 보입니다)
- 스킨 이름·응원 문구에 **구단명·별칭·슬로건**이 없는가 (금지어 목록)
- 기본 스킨은 `body` 가 비어 있는가 (= 정보 색 유지)
- 깎기 무늬·유니폼 무늬가 실제로 다양한가 (전부 `plain` 이면 의미가 없음)

특히 **"프론트엔드 소스를 읽어서 검사하는" 테스트** 3개를 권합니다. 파이썬과
JS 사이는 문자열로만 묶여 있어서, 한쪽만 고치면 조용히 깨지는 유일한 지점입니다.

```python
_HTML = open(FRONTEND, encoding="utf-8").read()

@pytest.mark.parametrize("pattern", [p for p in PATTERNS if p != "plain"])
def test_frontend_draws_every_pattern_on_screen_and_in_the_capture(pattern):
    """화면(patternSVG)과 📸 캡처(drawPattern) 둘 다 알아야 합니다."""
    screen = _HTML.split("function patternSVG", 1)[1].split("\nfunction ", 1)[0]
    canvas = _HTML.split("function drawPattern", 1)[1].split("\nfunction ", 1)[0]
    assert f'"{pattern}"' in screen, f"patternSVG 에 {pattern} 분기가 없습니다"
    assert f'"{pattern}"' in canvas, f"drawPattern 에 {pattern} 분기가 없습니다"
```

함수 몸통만 잘라서 보는 게 요령입니다. 파일 전체를 문자열 검색하면 다른
곳에 우연히 같은 단어가 있어서 **통과해 버립니다.**

## 8. 붙이는 순서 (체크리스트)

1. `Portfolio.skin` 문자열 한 칸 추가 + 저장/불러오기에 포함
2. `skins.py` 복사 → 기본 스킨 1벌만 남기고 나머지는 나중에
3. 기존 CSS 의 하드코딩 색을 `var(--turf-a)` 등으로 교체
4. `applySkin()` 추가 → 컴포넌트 args 로 `skin` 전달
5. 이 시점에서 **기본 스킨으로 예전과 똑같이 보이는지** 먼저 확인
   (여기서 안 같으면 색 변수를 하나 빠뜨린 것입니다)
6. `bodyOf()` 폴백 넣기 → 클럽풍 스킨 1벌 추가해서 몸통이 물드는지 확인
7. `textOn()` + 배너 → 대비 테스트
8. `patternSVG` ↔ `drawPattern` 짝 → 캡처 이미지와 화면 비교
9. `badgeParts()` 한 함수로 깃발
10. 나머지 스킨 20벌은 **데이터만** 추가 (코드 수정 0줄)

5번에서 한 번 멈추는 걸 강하게 권합니다. "스킨을 얹었는데 기본 화면이 미묘하게
달라진" 상태로 20벌을 추가하면 어디서 틀어졌는지 못 찾습니다.

```python
def is_unlocked(portfolio, skin_id) -> bool:
    return True      # 나중에 여기만 바꿉니다
```

보여주지 않는다는 규칙 때문입니다.
